# MTRAG generation runs — manifest

**Prior work** (searched before the runs, per CLAUDE.md):
`docs_search(source_type='memory', "MTRAG Task B Task C generation RAG answer quality GPT-4o judge
RL_F RB_llm RB_alg harmonic mean")` returned substantial prior art. Three findings bind these runs
rather than merely informing them, and they are reproduced in `benchmarks/mtrag/generation.py`'s
docstring: the withheld-metadata rule, the 1.0-on-all-three abstention lever, and the `RAG.json`
anchored-lift constraint restated as caveat 4 below.
Chiefly [[project-recall-mtrag-rbalg-probe-2026-08-05]] and
[[project-recall-mtrag-retrieval-coverage-bottleneck-2026-08-06]].

The `.predictions.jsonl` payloads are not vendored (16 MB, and `.gitignore`d in line with every
other prediction file in this repo). This records what produced them and what they hash to, so a
published number stays checkable without the payload in git.

Generated by `benchmarks/mtrag/generation.py`. Release under test:
`mtrag-human/generation_tasks/` from the MTRAG benchmark, 842 tasks, four domains
(clapnq, cloud, fiqa, govt).

## What is verified about these artifacts

Checked programmatically against the release, not asserted:

- 842 rows each, all task ids unique, covering exactly the 842 source task ids.
- **No withheld benchmark metadata in any submission row.** `Answerability`, `targets`,
  `Question Type` and `Multi-Turn` are top-level fields of the release that MTRAGEval withheld from
  participants; none appears in either output. `targets` is the gold answer itself.
- Every row carries the five fields `format_checker.py` requires for `rag_taskc`
  (`task_id`, `Collection`, `input`, `contexts`, `predictions`).
- Every `document_id` is a string, every `score` numeric, every prediction `text` a non-empty
  string, and no row exceeds `MAX_CONTEXTS = 10` (observed max: 9 for B, 5 for C).
- Both files are under the official 20 MB submission limit.

## Caveats that must survive into any writeup

1. **These are unscored.** No RL_F, RB_llm or RB_alg number exists yet; the official judge has not
   been run. Any abstention or quality figure derived from string matching over these files is
   indicative only, and my own attempts at that were wrong in both directions.
2. **Task B and Task C are not comparable as "abstention ability".** In Task B the 55 UNANSWERABLE
   tasks carry *no gold contexts at all*, so the model sees an empty passage list and the prompt
   tells it to say it does not know: the easy case. In Task C every task carries retrieved
   passages (`tasks_without_contexts: 0`), so an unanswerable question arrives with
   plausible-looking evidence that does not answer it. Only the second is the published baselines'
   0.0%–32.7% regime.
3. **Task C over benchmark contexts is not RE-call.** It uses `RAG.jsonl`, the benchmark's own
   retrieval, and exists as the generation-side control. Only the third run measures RE-call.
4. Per `project-recall-mtrag-rbalg-probe-2026-08-05`: recomputing the published table from
   `RAG.json` runs +0.018 to +0.043 high on every model, because the instance set is not the
   published one. A number from here is comparable as an **anchored lift** against baselines
   recomputed the same way, **not** against the published leaderboard directly.
