# Session open

Load the project's current instructions and session procedure. Ask Git for the real branch,
remote tracking position, worktrees and uncommitted changes. Establish workspace isolation
when the project requires it; a clean checkout and a startup hook do not prove ownership.
Preserve another session's files, containers and transports.

Use the `re-call` skill to search before planning or repeating prior work, then obtain focused
evidence when relying on a remembered constraint. Read index entries as pointers to memos.
When freshness matters, use `recall_stats` and current retrieval verdicts. Startup counts are
cached configuration, not evidence of live calibration, tool readiness or corpus currency.
Keep trusted evidence, an abstention, and an unavailable trust gate distinct.

Check configured audit memory and owner-reviewed general knowledge when relevant. These
capabilities depend on the deployment: use its documented corpus routes and queue commands.
Report missing or pending state; do not invent an empty corpus, approve a proposal, install
another server, or start a rebuild as a side effect of opening a session.

Inspect existing development resources without starting a database the task will not use.
Give a concise orientation report covering the branch, foreign changes, workspace ownership,
relevant unresolved memory, knowledge review queues and actual readiness gaps. Report a check
that did not run as unperformed. Respect deployment holds and the user's current instructions.
