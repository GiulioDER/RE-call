# Session close

Load the project's close procedure and the `re-call` skill. Review the actual branch,
uncommitted files and work not yet landed. Preserve unrelated changes and stage by explicit
path when a commit is authorized. Complete applicable deployment steps only within the user's
authorization and current deployment holds.

Record reusable facts through the configured memory path, with evidence, scope, why they
matter and how a future session should apply them. Update the memory index. Supersede changed
facts rather than silently rewriting their history. Keep credentials, private customer data
and unrelated projects out of memory.

Use the deployment's configured refresh path and respect active-worker ownership. The client
lifecycle may perform the normal refresh; a queued job, valid local memo or successful process
launch does not establish that new evidence is served. Inspect the result and verify retrieval
through the appropriate MCP server. Report blocked, deferred or unverified refreshes plainly.

When audit memory or owner-reviewed general knowledge is configured, include its documented
close steps and pending queue in the report. Keep corpora separate. Propose qualifying general
knowledge through the deployment's review path; a close request does not approve new entries
or accepted audit lessons. Do not invent an installation-specific command or tenant.

Clean up only resources positively owned by this session using the project's supported tools.
Let the client's SessionEnd lifecycle run; do not kill transports by age or command resemblance.
Report each applicable step with its evidence: completed work, tests and skips, cleanup,
knowledge proposals, corpus verification, and remaining blockers or handoff. A local report
script does not complete the rest of the checklist by itself.
