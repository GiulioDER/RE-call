Your data

Turn your own notes, decisions, and project memory into a searchable corpus.

A RE-call corpus is not just “some files in a folder.” It is a set of markdown documents whose text, validity hints, and metadata are worth trusting enough to retrieve later.

Simple mental model

Each markdown file is a memory unit. RE-call chunks it, embeds it, stores the vectors in PostgreSQL, and later decides whether any retrieved chunk is trustworthy enough to answer from.

Corpus shape

What good source material looks like

Good candidates

  • Project decisions with dates and clear outcomes.
  • Research notes that record what changed and why.
  • Customer specific facts you need to retrieve later.
  • One fact per file when the fact should be independently discoverable.

Weak candidates

  • Huge mixed notes files that bundle unrelated topics together.
  • Temporary scratch text with no durable value.
  • Files whose wording is vague enough that you cannot tell whether the idea is still valid.
  • Data you are not allowed to send through your chosen embedder path.
A practical beginner rule

If you want to ask a future agent “what did we decide about X?”, X should probably live in its own markdown file or in a very tightly scoped note.

Recommended layout

Start with the Claude memory pattern if you are unsure

The setup wizard can scaffold a `memory/` folder and a starter `memory/MEMORY.md`. That is the easiest structure to grow from.

Example structure 
memory/
  MEMORY.md
  pricing-model-decision.md
  retrieval-threshold-study.md
  customer-acme-onboarding.md
What `MEMORY.md` does

It acts as the always loaded index of your memory folder. Individual facts still live in their own markdown files, but `MEMORY.md` points to them and documents the convention.

Indexing

How to load your corpus into RE-call

Once your files are ready, index the folder you want RE-call to search.

Windows PowerShell and macOS shell 
python -m recall.cli index memory/
What happens during indexing

RE-call reads the markdown, splits it into chunks, generates vectors with your chosen embedder, and writes the searchable representation into PostgreSQL.

Calibration

Calibration is specific to your corpus and your embedder

The repo ships a demo query set and demo corpus. That is useful because it shows the workflow end to end. It is not enough to certify your own memory store.

Calibration type What it proves What it does not prove
Bundled demo calibration The command flow works and the labeled JSON format is correct. That the threshold transfers to your own corpus.
Your own labeled calibration That this exact corpus and embedder path were measured together. That the threshold will still hold after major corpus or model changes.
Important rule

If you switch embedder, change the corpus substantially, or rebuild the generation, assume you need to calibrate again.

Labeled queries

How to create a usable calibration set

Your JSON file needs at least one answerable query and at least one unanswerable query. Each entry needs a `query` and an `answerable` key.

Minimal example 
[
  {"query": "What is our current API limit?", "answerable": true},
  {"query": "Which habitat do we use on Mars?", "answerable": false}
]
How to think about “unanswerable”

An unanswerable query is a question your corpus should refuse because the answer is not there. Those examples are essential because RE-call is designed to abstain rather than hallucinate a nearest match.

Run it

Practice with the bundled sample, then measure your own data

First, locate the bundled sample files if you want a safe practice run:

Windows PowerShell and macOS shell 
python -c "import recall.eval, pathlib; print(pathlib.Path(recall.eval.__file__).parent)"

Then build your real calibration set and run the generation bound calibration flow from the technical docs. The pattern looks like this:

Create a draft measurement

One line example 
recall --tenant acme --serving-dsn "postgresql://user:pass@host:5432/dbname" calibrate --generation gen_... --queries queries.json

Create and publish

One line example 
recall --tenant acme --serving-dsn "postgresql://user:pass@host:5432/dbname" calibrate --generation gen_... --queries queries.json --publish
What “publish” means here

A measured artifact is not automatically active. The technical docs say publication is explicit, which is what makes a certified calibration become the one the tenant serves.

Do not ship the sample threshold as your production truth

The docs are explicit: calibration belongs to the corpus and embedder it was measured on. The sample is only a tutorial scaffold.
