Install path

Run the stack in the order RE-call expects.

The key point is sequence: database first, package install second, schema third, setup wizard fourth. If you reorder those, you create avoidable errors.

What this installs

A local PostgreSQL plus pgvector container, the RE-call package with the local FastEmbed path, and the initial schema for the default `chunks` table.

Step 1

Open the repo folder

Every command in this page assumes your shell is already inside the RE-call clone.

Windows PowerShell

PowerShell 
cd C:\path\to\RE-call

macOS Terminal

Shell 
cd /path/to/RE-call

Step 2

Start PostgreSQL plus pgvector with Docker

The repository already includes a `docker-compose.yml` for the quickstart database.

Windows PowerShell and macOS shell 
docker compose up -d --wait
Why this is the easiest route

The quickstart image already matches the repo documentation: PostgreSQL 18 with pgvector prepackaged. You skip the native extension install and service setup steps.

Step 3

Install RE-call with the local embedder path

For the first run, I recommend the `fastembed` extra because it keeps embeddings local and matches the README quickstart.

Install from PyPI

Windows PowerShell and macOS shell 
pip install "recall-rag[fastembed]"

Install from the cloned repo

Windows PowerShell and macOS shell 
pip install -e ".[fastembed]"
Which one should you choose?

Use PyPI if you only want the product. Use editable mode if you want to modify the repo and have Python see your local changes immediately.

Step 4

Apply the schema before you run setup

This creates the baseline schema on the default `chunks` table and includes the migration path the wizard expects.

Windows PowerShell and macOS shell 
python -m recall.cli --migration-dsn postgresql://recall:recall@localhost:5432/recall schema --dim 384 apply
Why `--dim 384` matters

The local FastEmbed default used in the quickstart produces 384 dimension vectors. The schema width needs to match the embedder width you plan to use.

Why I do not start with `--table something_else`

The README notes that global migrations must first be applied to the default target. Starting there avoids `SchemaTooOld` on a fresh database.

Step 5

Run the guided setup wizard

The wizard records your embedder and retrieval choices. It can also scaffold Claude related files and run a demo calibration if you provide labeled sample data.

Windows PowerShell and macOS shell 
python -m recall.cli setup

  1. Choose the local embedder

    For most beginners, `fastembed` is the clean answer because it stays local and follows the documented quickstart.

  2. Skip reranking unless you already want the quality upgrade

    Reranking is useful, but it is not necessary for the first install and it adds latency plus an extra dependency path.

  3. Say yes to scaffolding only if you want Claude files in this project

    If you are only testing the local database and CLI, you can add the Claude scaffold later.

  4. Use the demo calibration only as a practice run

    The sample proves the mechanism. It does not certify your own future memory corpus.

Step 6

Smoke check the install

If setup completed, do one simple index and search cycle before you move on.

Index the example corpus

Windows PowerShell and macOS shell 
python -m recall.cli index corpus/

Search it

PowerShell 
$env:RECALL_TRUST_MODE = "development"
python -m recall.cli search "what did we decide about rate limits?"
Shell 
RECALL_TRUST_MODE=development python -m recall.cli search "what did we decide about rate limits?"
Why this uses development mode

Until you have a published certified calibration, development mode makes the local demo path explicit instead of pretending the trust gate is already production ready.
