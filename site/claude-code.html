Claude integration

Connect RE-call so Claude can check memory before it acts.

This is the practical goal: Claude asks RE-call what the memory already says, then uses that answer to avoid repeating a dead idea or trusting a weak match.

What changes after connection

RE-call becomes an MCP tool server. Claude can call tools like `recall_search` and `recall_evidence` directly instead of relying on pasted notes.

Step 1

Install the MCP extra

If you installed only the base local path earlier, add the `mcp` extra now.

Windows PowerShell and macOS shell 
pip install -e ".[fastembed,mcp]"

Step 2

Add the RE-call MCP server to Claude Code

The repo docs show this `mcpServers` block for local development mode:

.mcp.json snippet 
{
  "mcpServers": {
    "recall": {
      "command": "python",
      "args": ["-m", "recall_mcp.server"],
      "env": {
        "RECALL_SERVING_DSN": "postgresql://recall:recall@localhost:5432/recall",
        "RECALL_TENANT": "default",
        "RECALL_TRUST_MODE": "development"
      }
    }
  }
}
Where this goes

For Claude Code, save it as `.mcp.json` in the project root, or use the documented CLI command: claude mcp add recall -- python -m recall_mcp.server.

Why development mode is here

This local example is for an uncalibrated development setup. The technical docs say to remove `RECALL_TRUST_MODE` in production after you have an active generation with a published certified calibration.

Scaffolded files

What `recall setup` writes for Claude projects

The setup wizard can scaffold two things after its embedder and retrieval prompts:

File What it does Important behavior
`CLAUDE.md` block Adds a `` to `` section that tells Claude when to call RE-call tools and how to record new durable facts. Re-running setup replaces only that marked block, not the rest of your file.
`memory/MEMORY.md` Creates the starter memory index and documents the expected frontmatter and one line per fact pattern. It is only created if it does not already exist.
Why this matters

These files teach Claude that memory is a tool driven workflow: search first, answer carefully, and write durable facts back into the memory folder in a consistent format.

Auto-index

What the setup wizard tries to do next

After scaffolding, the wizard tries to index `memory/` immediately so Claude can search it from the first turn.

  1. It only works if the schema already matches the chosen embedder width

    If the schema is missing or at the wrong dimension, setup prints remediation instead of blocking forever.

  2. Production mode skips local auto-index

    The docs note that under `RECALL_ENV=production`, this local filesystem indexing step is skipped entirely.

  3. Default tenant and table are used

    If your project uses non-default values, index the folder yourself against the correct target later.

One subtle beginner surprise

The first auto-index can index `memory/MEMORY.md` itself. The docs say that is usually harmless, but if Claude surfaces that file, this is why.

Tool behavior

How Claude should use RE-call

Use `recall_search` first

Claude should call it before proposing an idea, revisiting prior work, or repeating a hypothesis.

Use `recall_evidence` before answering from memory

This path is for citation ready evidence, not only a quick “have we seen this?” check.

Respect abstentions

If RE-call abstains, Claude should say it does not know instead of manufacturing certainty from low quality hits.

Write durable facts into `memory/`

Keep stable, valuable knowledge in files that can be re-indexed, not only in chat history.
