# Pre-registration: does the next C9 version keep Coding retrieval? (arm K4)

**Date:** 2026-09-26   **Status:** predicted, not yet measured

## The question

The Coding Full will run on a new C9 version (user decision, 2026-09-26): the served `3eb447c4`
(dated Search content, prior records sent to the compiler without ids) plus #775 (a cut-off
compile is not resent; payloads over 150,000 encoded characters are not compiled). The Coding
retrieval screen last measured C9 before any of those changes except the date header: K0 and K0b
(served then) and K3 (dated Search content) all scored MRR 0.8627, recall@10 34 of 34, with
identical per-task results. The prior-record and cost changes act at Add time, on the compiled
records that feed the grounded graph (which may promote two raw items into ranks 9 and 10) and the
Context4 index. Does the new version keep Coding retrieval?

## Design

`scripts/aml_c9_coding_window_check.py collect --arm K4 --dated-search-content` with `recall_aml`
from this branch (`claude/c9-compile-cost`, the commit of this record), in a fresh database
(`codingcheck_k4_20260926`) on VPS3, the same frozen AMB Coding screen (196 sessions, 34
prompts, one message per event), the served C9 variant as this branch defines it. Compared by
`report` with K0, K0b and K3 of 2026-09-24/25, unchanged on VPS3.

## Decision rule, fixed now

N is the noise floor |K0b minus K0| on MRR (0.000 measured).

1. Apparatus failure (below): report, decide nothing.
2. **Keep** if K4 MRR is at least K0's minus (0.02 + N), recall@10 at least 33, and recall@100
   34.
3. **Otherwise report** the tasks that moved and hold the Coding Full until the user decides.

## Apparatus checks

1. `/version` of K4 reports the C9 variant, `message-content-only-v1`, `created-at-header-v1`,
   `anchor_prior_records: without-ids` and `anchor_compile_max_payload_chars: 150000`.
2. K4 writes 1,220 raw windows, the same count as K0.
3. No Add or Search failure.

## Confounds

A proxy: our synthetic AMB Coding screen, not AML's Coding data (the only AML Coding evidence
is a smoke whose Solve stage failed on the platform's side). OpenRouter does not pin a provider,
so the compiled records can differ run to run; retrieval ranking of raw windows does not depend on
them.
